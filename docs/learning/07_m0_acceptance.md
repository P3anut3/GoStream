## 已验证：真实 HTTP + MySQL 双账号

测试入口：cmd/server/main_test.go 的 TestGinGORMHTTPIntegration，使用生产路由。
测试账号为当次随机名称，上传文件存于临时目录，结束后清理精确匹配的测试记录；不删除已有用户或作品。测试会消耗自增 ID。

1. A/B 注册登录，重复用户名被拒绝。
2. A 上传文件；B 使用 A 的地址发布返回 403。
3. A 发布成功，uploads 状态变为 published。
4. 游客可读详情与媒体；Range 请求返回 206 和正确字节范围。
5. B 无权删除 A 的作品（404），游客删除返回 401；A 的作品仍可读。
6. B 的个人作品列表不包含 A 的作品。
7. A 点赞/取消正确；B 重复点赞仍只有一条记录。
8. A/B 看到总数相同，自己的 liked 状态不同。
9. B 提交评论时伪造 user_id=A，实际作者仍为 JWT 中的 B。
10. A/B 不能删除对方评论；当前产品规则下，视频作者也不能删除他人评论。
11. A 删除自己的作品后，详情返回 404，相关点赞/评论被外键级联清除。

该 HTTP 测试的 MP4 是类型识别测试字节，验证传输正确，不用于证明浏览器能解码播放。
另有 TestFeedHTTPMySQLIntegration 验证 Feed 游客与 A/B 的批量信息、分页及固定查询次数。

## 后端学习重点：写权限必须落在实际操作条件中

阅读顺序：cmd/server/main.go 的 DELETE 路由 → internal/auth/middleware.go 的 JWTAuth → internal/video/handler.go 的 Delete。

```text
JWT 中的 userID：谁正在操作
路径中的 id：操作哪个视频
WHERE id = ? AND author_id = ?：同时限定目标和归属
RowsAffected == 0：不存在，或者不属于当前用户
```

前端隐藏删除按钮只是界面行为，不能阻止别人自己构造 DELETE 请求。
当前后端用同一条 DELETE 的两个条件执行权限约束；不能为了简化改成只按 id 删除。
本轮没有更改业务实现；没有为了推进学习强行制造新重构任务。
